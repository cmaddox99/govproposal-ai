💡
What this product is about: Software at the boarding gate — from the moment a flight event fires in operations control to the moment a passenger boards or a bag is checked. Four integrated domains: digital displays, biometric boarding, carry-on compliance, and ops communications. The root failure mode across all four is the same: decision latency — the right information arriving too late for the agent or controller to act on it correctly.
🏗️

Use Cases

Happy paths, exception paths, and non-negotiables for each domain.

📺 Real-Time DSS Display Update

FAR Part 139 DOT 14 CFR 259

AOC fires a flight ops event → propagates to all display surfaces (GIDS, FIDS, BIDS, WIDS) within 5 seconds. The tarmac timer is always visible in the primary GIDS view — never behind a tab.

Happy Path — Gate Change (IROP)

  1. Ops Controller fires gate-change in AOC (C14 → C22)
  2. AOC publishes to Azure Service Bus
  3. DisplayHub consumer processes event (target ≤2,000ms)
  4. Flight state cache updated with new gate
  5. GIDS at C14 shows "Gate Changed → C22"; GIDS at C22 shows inbound flight
  6. Audit record created: flight_id, old_gate, new_gate, staleness_ms

Non-Negotiables

  • No polling AOC — consume from Service Bus only
  • Staleness SLA: 5 seconds AOC publish → GIDS render
  • Tarmac timer in primary GIDS view always (DOT mandate)
  • Every state transition emits audit record with staleness_ms
  • Gate context (flight_id, gate_id, timestamp) on every log event

Acceptance Criteria

  • Gate change: both GIDS surfaces updated within 5,000ms
  • Tarmac timer visible in primary view within 5,000ms of door-close
  • Staleness metric wired to App Insights per surface (Sprint 1)
  • Consumer lag alert: threshold >3s sustained >1min

🤳 Touchless Biometric Boarding

TSA 49 CFR 1542 CBP Biometric Exit GDPR/CCPA

Passenger presents face at gate podium → CBP TIS facial match → APPROVE / DENY / OPT-OUT in ≤3 seconds. Gate agent monitors and handles non-matches and opt-outs. Biometric PII never reaches operational logs.

Happy Path — Enrolled Passenger

  1. Camera captures face frame at gate podium
  2. Biometrics API → Apigee → CBP TIS facial match
  3. TIS returns MATCH above threshold
  4. API verifies PNR active + flight open for boarding
  5. Podium shows green APPROVED; DCS boarding record updated
  6. Audit: pnr_token, gate_id, match_result: APPROVE — no raw template, no match score

Non-Negotiables

  • Opt-out always reachable without agent involvement
  • Match threshold changes require supervisor auth + CBP notification
  • Every DENY has a typed reason code — no generic "FAILED"
  • No biometric PII (templates, scores) in operational logs — ever
  • Raw biometric deleted ≤12h post-departure (CBP mandate)

Acceptance Criteria

  • Throughput ≥22 pax/min at pilot gate (Sprint 0 baseline)
  • False non-match rate ≤1.5% at pilot gate
  • Opt-out reachable in ≤2 taps, without agent
  • Zero log entries with biometric template or match score

🧳 Carry-On Baggage Compliance

DOT 14 CFR 259 DOT Consumer Protection

Agent scans/measures carry-on → bag matrix returns COMPLIANT / GATE-CHECK / DENIED with rule version → agent enforces. Station Manager updates rules from admin UI without engineering. Every decision is immutable in the audit log.

Happy Path — Policy Update

  1. Manager creates updated rule in Bag Matrix Admin UI
  2. UI requires: rule_id, effective_date, change_reason, manager_id
  3. New rule version published (e.g. v2.4.2)
  4. Admin UI shows per-gate propagation: N/M gates updated
  5. All gates at station running new version within 60 seconds
  6. Audit: rule_version, changed_by, change_reason, propagation_timestamp

Non-Negotiables

  • Rule version logged with every decision (COMPLIANT, GATE-CHECK, DENIED, MANUAL)
  • Override requires supervisor auth — blocked at UI without it
  • Policy propagation ≤60 seconds — status visible in admin UI
  • No in-place edits — every change is a new versioned entry

Acceptance Criteria

  • Every decision returns rule_version in response and displays it to agent
  • Override path: UI blocks without supervisor auth code — zero silent overrides
  • Propagation p95 ≤60s; failure alert within 90s
  • Bag matrix p95 latency ≤2,000ms from scan to decision

📲 Connect Me — Flight Event Notifications

FAR Part 139 Load Control Traceability

Flight ops event fires → right person (gate agent, ramp crew, FLC) receives an actionable Teams message before their decision window closes. Push only — no polling.

Happy Path — Gate Change Alert

  1. Ops Controller fires gate-change in AOC (C14 → C22)
  2. AOC publishes to Azure Service Bus
  3. Connect Me consumer processes event (target ≤2,000ms)
  4. Teams message sent to gate agent: "⚠️ GATE CHANGE — AA 1234 | C14 → C22 | Please confirm"
  5. Agent taps CONFIRM on task card
  6. Audit: event_type, recipient_id, delivered_at, actioned_at, delivery_latency_ms

Non-Negotiables

  • All operational alerts are push — agents must never poll for status
  • FLC task cards always show load plan version and timestamp
  • All workflow completions logged with actor_id + task_version + timestamp

Acceptance Criteria

  • Gate change alert delivered within 30,000ms of AOC publish (p95)
  • Load plan card shows version and timestamp on 100% of tasks
  • Unconfirmed gate change: escalation triggered after 5 minutes
  • Unread alert rate metric: alert if >5% unread within 5 minutes

Open Discovery Questions

The questions we must answer before building anything. These are the baseline gaps — hypotheses, not facts.
🛑
PRD-1.2 — Problem-First Law: Do not propose a solution until you have a measured baseline. The questions below are the field work that unlocks building.

📺 Digital Signage

Problem candidate: Gate displays show stale flight status during irregular operations.
  • What is the current measured staleness (ms) from AOC event to display update — and at which layer is the lag worst: hand-off, consumer, or render pipeline?
  • Do gate agents actually trust the GIDS display, or have they already built verbal workarounds that bypass it entirely?
🔴 Do not build until: staleness baseline per display type + one confirmed incident where staleness caused a wrong agent decision.

🤳 Biometric Boarding

Problem candidate: False non-matches delay passengers and erode agent trust in the system.
  • What is the current false non-match rate (%)? Is it uniform across gates or concentrated at specific hardware or lighting conditions?
  • What is boarding throughput (pax/min) biometric vs. manual scan? Is biometric boarding actually faster in practice?
  • Is the opt-out path genuinely findable without agent help? Have we observed passengers in the field?
🔴 Do not build until: false non-match rate baseline, confirmed agent understanding of reason codes, opt-out usability confirmed by field observation.

🧳 Carry-On Baggage

Problem candidate: Inconsistent enforcement due to rule version lag across gates.
  • What is the current gate-check rate — and does it vary across gates in ways that suggest different rule versions are running?
  • What is the override rate? Are overrides concentrated at specific agents or specific policy rules?
  • How long does it currently take a policy change to reach all gates, and does anyone measure it today?
🔴 Do not build until: gate-check rate baseline, confirmed rule version visibility gap, propagation time measurement.

📲 Connect Me

Problem candidate: Flight event alerts arrive after the agent decision window closes.
  • What is the current time from AOC event fire to agent-aware-and-acting? Where is the lag — pipeline, Teams delivery, or notification visibility on the device?
  • What percentage of operational alerts go unread? Which alert types have the highest unread rate?
  • Can FLC confirm load plan currency from the task card today — or do they always need to open the load control system to check?
🔴 Do not build until: measured alert latency baseline, unread rate by alert type, confirmed FLC load data version visibility gap.

Regulatory Constraints

These are not preferences — they are hard product boundaries. Getting them wrong has legal and operational consequences.

FAR Part 139

Airport certification — applies to all gate operations systems. Every state transition must be auditable.

TSA 49 CFR Part 1542

Airport security — governs biometric boarding and gate access. Match threshold changes require CBP notification.

CBP Biometric Exit Mandate

Facial recognition boarding. Raw biometric data deleted ≤12h post-departure. Audit retention: 7 years.

DOT 14 CFR Part 259

Tarmac delay and consumer protection. Tarmac timer must be in primary GIDS view — never a sub-screen.

GDPR / CCPA

Biometric PII for international passengers. Opt-out path must be accessible without agent assistance.

DOT Consumer Protection (Baggage)

Governs baggage disclosure and denied boarding. Every carry-on decision must be auditable with rule version.
