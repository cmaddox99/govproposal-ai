7. Agentic Compliance Feedback Loop — ENG-12 ⛔
🔄 Constitutional Gate Flow (ENG-12.1)
The SonarQube dashboard is the human-in-the-loop contract. The agent does the work. The human stays in the loop by watching FAIL → PASS.
AGENT
Completes phase work (Atomic TDD, refactor, review)
↓
AGENT
Runs SonarQube scan (skill-sonarqube-compliance-gate)
↓
SONAR
Returns gate API result (pass/fail)
API result alone ≠ compliance
↓
HUMAN
Reviews dashboard — THE mandatory checkpoint. Agent cannot advance without this.
↓
HUMAN
Approves phase advance (or directs remediation)
PASS ✓
↓
AGENT
Proceeds to next phase

🧭 Questions to Explore — Coaching Notes (Senior Architect Socratic Path — DC-06)

Use these open-ended questions with your team to build constitutional fluency. These are NOT required steps — they are optional coaching prompts for experienced practitioners.

  1. Architecture review: Looking at the three pillars (ENG / PRD / BUS), which pillar is most underrepresented in your team's current pull request reviews — and what law would close that gap first?
  2. Non-negotiable exposure: Of the 13 ⛔ Non-Negotiable laws, which two would be hardest to retrofit into your current system architecture, and why?
  3. RAG model trust: If the law registry version bumped tomorrow and your pages weren't re-rendered, which auto-generated page (P2, P4, P5, P6) would be most dangerous to leave stale — and for which team?
  4. Governance gaps: Scan the 23 product domains in the RAG model. Which domain is closest to your team's current sprint work, and is there a constitution-governed workflow already covering it?
  5. Adoption blockers: Steve Fraser's survey identified "trusting the AI" as the #1 adoption barrier. What evidence would a skeptical engineer on your team need to see in a pull request before trusting a constitutionally-governed change?
