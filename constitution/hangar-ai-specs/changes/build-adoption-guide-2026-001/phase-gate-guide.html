🤖 Non-Determinism & Human Agency

🔑 DC-11: Your Approval is the Constitutional Gate

These workflows are non-deterministic. The agent's output varies between runs. Your job at each phase gate is to:

  1. Read the evidence artifact carefully
  2. Ask: does this match my intent?
  3. APPROVE to proceed, or OBJECT to scope down or re-propose

Your approval is the constitutional gate. It is never automatic.

📁 What Is a Phase Gate Artifact?

A phase gate artifact is an HTML file stored in hangar-ai-specs/changes/[spec-id]/ and named phase-N-[name].html. It is produced by the AI agent at the end of each phase and contains structured evidence for your review.

┌─────────────────────────────────────────────────┐ │ HEADER: Workflow ID · Phase N · Status │ ├─────────────────────────────────────────────────┤ │ EVIDENCE TABLE: What was found/done this phase │ ├─────────────────────────────────────────────────┤ │ GATE STATUS: ✅ PASS / ⚠️ WARN / ❌ FAIL │ ├─────────────────────────────────────────────────┤ │ DECISION ROW: Human approved/objected + reason │ ├─────────────────────────────────────────────────┤ │ COMMIT HASH: Links to the code change │ └─────────────────────────────────────────────────┘
HEADER Identifies the workflow ID, current phase number, and overall status at a glance.
EVIDENCE TABLE Structured rows of what the agent found or changed during this phase — the raw facts.
GATE STATUS Machine-evaluated signal: ✅ PASS, ⚠️ WARN, or ❌ FAIL. Not a substitute for human review.
DECISION ROW Where you record APPROVE or OBJECT along with the reason. Required before the next phase begins.
COMMIT HASH SHA of the code change associated with this phase — links evidence to source control.

🚦 Decisions at Each Gate Type

What you're reading

A PROPOSAL.md rendered as HTML — contains the problem statement, law citations, scope boundaries, and kill-if criteria.

What to check

  • Problem statement matches your intent — not the agent's interpretation of it
  • Law IDs are real and applicable (e.g., ENG-4.1, DC-11) — not invented identifiers
  • Scope is appropriate — not too large, not spanning multiple bounded contexts
  • Kill-if criteria are measurable and time-bounded (not vague)

Decision

✅ APPROVE — "The proposal matches my intent and scope"
❌ OBJECT — "Revise the proposal: [specific change]"
📐 Scoping example "Scope this adoption to setup and AGENTS.md only — defer SonarQube and avatar creation to a separate session."

What you're reading

A phase-N-[name].html file — structured evidence of every file the agent changed, why, and what tests were updated.

What to check

  • Changes match the approved proposal — no unrequested additions
  • No extra files modified outside the agreed scope boundary
  • Tests were updated alongside production code
  • Commit message references the proposal ID

Decision

✅ APPROVE — proceed to ARCHIVE phase
❌ OBJECT — "Revert [specific files] and re-implement within scope"

What you're reading

The final archive confirmation — showing the proposal moved to hangar-ai-specs/archive/ and all phase artifacts committed.

What to check

  • Proposal was moved (not deleted) to hangar-ai-specs/archive/
  • All phase artifacts are committed to source control
  • PROGRESS.md updated to reflect the completed phase

Decision

✅ APPROVE — the governed trail is complete
❌ OBJECT — "Archive is missing artifacts: [list what's absent]"

What you're reading

A sonarqube-delta.md file — comparing baseline metrics vs. current metrics for this change set.

Key metrics to review

  • coverage — overall project coverage (context only)
  • new_coverage — coverage of new code only (constitutional threshold)
  • vulnerabilities — must be 0 for Phase 4+
  • bugs — no new bugs introduced
  • code_smells — no new smells on new code

What to check

  • No NEW issues added — the constitutional rule targets new debt, not pre-existing
  • new_coverage ≥ configured threshold for this phase
  • vulnerabilities = 0 for Phase 4 and beyond

Example comparison table

Metric Before After Change Status
new_coverage — 84.2% +84.2% ✅ PASS
vulnerabilities 0 0 0 ✅ PASS
bugs 3 3 0 new ✅ PASS
code_smells 12 14 +2 new ⚠️ WARN

Decision

✅ APPROVE — no new issues introduced
❌ OBJECT — "New [metric] violations detected; resolve before proceeding"
📌 Important Pre-existing violations (bugs, smells, coverage gaps) do NOT block adoption. Only violations on new code in this change set are constitutional blockers.

What you're reading

A mutation test HTML report located in hangar-ai-specs/evidence/mutation-report/ — showing which synthetic code mutations were killed by the test suite and which survived.

Thresholds by phase

  • Legacy Rescue Phase 4 — mutation score ≥ 70%
  • Phase 7 (full constitutional) — mutation score ≥ 90%

What to check

  • Mutation score meets the threshold for this phase
  • Surviving mutants have been reviewed individually
  • Each surviving mutant has either a killing test added or an explicit acceptance note (e.g., "trivial getter — accepted")

Decision

✅ APPROVE — score meets threshold and surviving mutants reviewed
❌ OBJECT — "Mutation score is [X]% — below [threshold]%. Add killing tests for surviving mutants."

⚠️ Detecting AI Drift

⚠️ Signs the AI Has Drifted from the Constitution
  1. 1. Proposal cites no law IDs
    → Ask: "Re-propose and cite the specific law IDs that govern each decision."
  2. 2. Proposal scope grew between sessions
    → Ask: "What changed in the scope from the previous proposal? Revert to the approved scope."
  3. 3. ARCHIVE step was skipped
    → Do not start next phase. Say: "Archive the completed proposal before proceeding."
  4. 4. SonarQube gate was not consulted
    → Pause. Say: "Run the constitutional gate and show me the sonarqube-delta.md before we continue."
  5. 5. Phase artifact references laws that don't apply to this project
    → Ask: "Explain why [law ID] applies to this change."
  6. 6. Agent proposes fixing ALL pre-existing violations
    → Detect: proposal mentions "fix existing X issues", lists violations from before your change, or scope includes files you didn't touch. Correct: "The constitutional gate only requires no NEW violations. Scope to new code only — remove any pre-existing issues from this proposal."

🔭 Monitoring Across Sessions

Use these prompts in your next session to audit constitutional health without starting a new workflow.

📋 Summarise all open proposals

Summarise all open proposals in hangar-ai-specs/changes/ for this repo. List the proposal ID, status, and last phase completed.

🔍 Review a phase artifact for drift

Review phase-[N]-[name].html in hangar-ai-specs/changes/[spec-id]/ and tell me: (1) what evidence was produced, (2) what gate status was reached, (3) any signs of constitutional drift.

📐 Re-propose with reduced scope

The current proposal scope is larger than I want. Re-propose scoped to [bounded context — e.g., com.aa.loyalty.mileage package only]. Keep all other constitutional requirements.
