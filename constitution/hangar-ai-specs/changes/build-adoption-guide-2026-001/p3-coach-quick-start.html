🤖 What is the agent doing? DC-03

🤖 Agent Role Explainer DC-03

This is the #1 time sink in every session — answer it before they ask.
📖
When you run the adoption prompt…
The agent reads the constitution (all 168 laws, skills, and avatars in the RAG model) and analyses your project's code, structure, and existing tooling. It is building a PROPOSAL — a governed plan for adoption that it will show you before doing anything permanent.
Why a proposal? Because every action the AI takes must be reviewed and approved by a human first (BUS-1.1 ⛔ Human Oversight Law). The proposal IS the governance artifact.
📋
When the proposal appears…
The agent has STOPPED and is waiting for your decision. You will see a structured document: problem statement, proposed changes, law citations, and an APPROVE / OBJECT gate. Nothing has been changed in the codebase yet.
APPROVE means: "proceed with this proposal." OBJECT means: "I have a concern — here is my objection." You can reduce scope, change direction, or ask clarifying questions at this gate.
🔨
When you APPROVE…
The agent begins the IMPLEMENT phase — making the actual changes to the repo: creating AGENTS.md, updating configuration, adding initial tooling. It will commit with a message referencing the proposal.
The commit is traceable back to the proposal — that traceability IS the constitutional audit trail (ENG-11.2).
📁
When IMPLEMENT finishes…
The agent ARCHIVES the proposal — moving it from active to the archive, closing the constitutional loop. Your repo now has a governed history: proposal → implementation → archive.
This is the SDD cycle: PROPOSE → IMPLEMENT → ARCHIVE. Every future change follows the same loop. The team now has a repeatable, auditable process.
🧭 How agentic workflows work DC-07

🧭 Human Agency & Adaptive Scope DC-07

These are not scripts. You are in charge at every gate.
1
These workflows are non-deterministic
Constitutional workflows (adoption, legacy rescue, greenfield) are probabilistic guidance systems, not deterministic scripts. The same prompt run twice may produce different proposals — that is by design. The agent reads the constitution and your context and proposes a path. Always review before approving.
2
You control batch size
The AI will always propose the full scope it can see. You are not obligated to accept the full proposal. At every APPROVE / OBJECT gate, you can reduce scope, split the proposal into chunks, or defer sections to a later session. The constitution expects iteration — a smaller approved change done well is better than a large one done poorly.
3
Adoption is compositional
You can adopt the constitution in parts, in any order, across multiple sessions. Each of these is a complete, valid adoption outcome on its own:
✅ Setup + AGENTS.md only → commit → stop
✅ Code analysis + recommendations → review → stop
✅ SonarQube adoption → separate session
✅ Product avatar creation → when the team is ready
4
SonarQube gate = no new debt, not zero debt
The constitutional SonarQube gate enforces one rule: new code introduced in this changeset must not add new issues. It does NOT require fixing all pre-existing violations before adoption can succeed.
✅ Gate passes when: your changeset introduces zero new SonarQube issues.
❌ Gate fails when: your changeset introduces new issues above the baseline.
Large codebases with existing technical debt can adopt constitutionally without first resolving every prior violation.
5
Scope to a bounded context
You can scope any constitutional workflow to a single module, package, or bounded context. Running legacy rescue on com.aa.loyalty.mileage is a constitutionally valid, complete outcome — not a partial failure. Work iteratively: one package, commit, verify, continue.

The agent will produce a PROPOSAL document. Stop before approving. Walk the team through it together:

What to look for in the proposal
  • Problem statement — does it correctly describe the adoption goal?
  • Law citations — are the referenced laws relevant to this project?
  • Scope — is the batch size appropriate, or is it proposing too much at once?
  • Kill-if conditions — understand what would cause the agent to stop

Remember: you can OBJECT to reduce scope. Tell the agent: "Scope this adoption to setup and AGENTS.md only — defer SonarQube and avatar creation to a later session." The agent will revise the proposal.

How do we get the latest constitution updates?
Re-run the adoption prompt at any time. It checks if the constitution is already cloned and pulls the latest if so. The agent will propose only what has changed since your last adoption.
How do we handle multiple repos that all change together?
Run the adoption workflow in each repo separately. Each repo gets its own AGENTS.md, its own proposal history, and its own governed commit trail. Cross-repo coordination is handled at the proposal scope level — propose changes that span repos as separate linked proposals.
How do we know the agent is actually using all the laws?
The constitution is in the parent directory (./../hangar-ai-constitution/). The adoption workflow reads it directly. Every proposal cites the specific law IDs it is governed by — if a law applies to your change, you will see its ID in the proposal. If a citation is missing, you can OBJECT and ask the agent to re-examine.
What is the process to amend or override a law?
The amendment process is documented in the constitution itself. You can propose a local law override for your project (added to your repo's local-laws/ directory) or submit a formal amendment proposal to the constitution maintainer. See P10 — Amendment Process (coming next in the guide).

Coaching Notes
🎓 Socratic Coaching Prompts — Advanced coaches only Optional · DC-06 · Expand after the direct path is complete

Use these open-ended questions after your team has completed the direct adoption steps. These are for experienced coaches applying a Socratic layer — not for first-session use.

  1. On constitutional purpose: Now that the agent has produced a proposal, what do you think it was trying to protect by requiring a review gate before making any changes?
  2. On batch size decisions: Looking at the proposal scope the agent suggested, what would happen to team confidence if you tried to approve everything at once vs. approving it in three sessions? What's the right batch size for this team right now?
  3. On law applicability: The agent cited specific laws in this proposal. Pick one citation you're unsure about — can you find the law in the constitution and explain why it applies here?
  4. On process sustainability: How would you explain the PROPOSE → IMPLEMENT → ARCHIVE cycle to a new engineer joining this team in six months who has never seen a constitutionally-governed PR?
  5. On resistance: What's the most likely objection your team will have after their first independent run — and what evidence from the proposal process could you use to address it?
