DC-08 🎯 When to Use This Workflow

✅ Use Adoption when:

  • ✅ The repo does NOT have a hangar-ai-constitution/ directory adjacent to it
  • ✅ There is no AGENTS.md at repo root
  • ✅ There is no hangar-ai-specs/ directory
  • ✅ You are about to run Legacy Rescue, Greenfield, or any other workflow for the first time
  • ✅ Your AGENTS.md is stale or references the old brownfield guide
  • ✅ An openspec/ directory exists (pre-rename legacy — migration required)

❌ Do NOT run Adoption if:

  • ❌ hangar-ai-constitution/ and AGENTS.md already exist — adoption is complete
  • ❌ You just want to run a scan — use Legacy Rescue Phase 1 instead
  • ❌ hangar-ai-specs/evidence/adoption-verified.md exists and is current
🎲

DC-11 · Non-Determinism Notice — This workflow is non-deterministic. The agent may produce different AGENTS.md content or different phase artifact structures between runs. Both can be constitutionally valid. Your APPROVE at each gate is the constitutional checkpoint — not the agent's output format. Review artifacts for intent and completeness, not exact wording.

DC-10 🏛 Phase Gate Evidence — Phase 2b: Provision Gate

Updated hangar-ai-specs/evidence/adoption-check.md with gate fields:

Confirm gate_provisioned: true, sonar_token_gitignored: true, and the SonarQube dashboard is open and shows your project (even if "no analysis yet" — that is the confirmed starting state).

OBJECT — Any of the three conditions unmet — do not advance.

  • Sonar baseline shows 0 files scanned after first analysis → SonarQube not connected — check instance URL and project key

  • Dashboard shows different project key than adoption-check.md → Mismatched provisioning — delete project in SonarQube and re-run provision.sh with correct key

  • Artifact verdict: PASS but hangar-ai-specs/ subdirectory is missing archive/ or specs/ → Incomplete directory structure — re-run Phase 2.3 and re-verify

🔧 Adaptive Scope — Adoption Scoping Guidance

1. Scope adoption to setup only

Skip SonarQube (Phase 2b) if your project isn't ready. Adoption is still constitutionally valid without it — you can provision the gate later.

2. Run adoption per bounded context

If your repo is a monorepo, adopt one module at a time. Each module gets its own AGENTS.md binding scoped to that module's root.

3. Avatar creation is optional at adoption

You don't have to run the Avatar workflow immediately. Adopt first, add avatar context later. Use the base constitution without avatar enrichment and note this in AGENTS.md.

4. Phase 2b dashboard is never skipped

Even if SonarQube is already provisioned, Step 2b.3 (open the dashboard) must occur before every workflow session begins. This is ENG-12.2 — the human engagement contract.
