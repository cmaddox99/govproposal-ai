Phase 9.2 Before / After — Rich Aggregate Root (MileageAccount)

Sub-phase 9.2 hardened all 3 aggregate roots with invariant-enforcing state machines. MileageAccount is the canonical example: a pure data bag transformed into an invariant-enforcing aggregate root.

❌ BEFORE — Anemic Model (Phase 8 End)
// No invariants, no behaviour
// ENG-2.2 violated — domain is empty

public class MileageAccount {
    private Long id;
    private boolean frozen;   // raw boolean
    private String status;    // raw String
    private int balance;
    // getters/setters only — no guards
}

// Business logic scattered in service:
public void freezeAccount(
        String accountId, String reason) {
    MileageAccount acct =
        repo.findById(accountId);
    acct.setFrozen(true);  // no state guard
    acct.setFreezeReason(reason);
    repo.save(acct);
    // What if already frozen? Silently broken.
}
✅ AFTER — Aggregate Root (ENG-2.4, ENG-3.2)
// Invariant-enforcing aggregate root
// Domain owns its state machine

public class MileageAccount {
    private UUID id = UUID.randomUUID();
    private AccountStatus status   // type-safe
        = AccountStatus.ACTIVE;

    public void freeze(String reason) {
        if (status != AccountStatus.ACTIVE) {
            throw new IllegalStateException(
                "Only ACTIVE accounts "
                + "can be frozen");
        }
        this.status = AccountStatus.FROZEN;
        this.freezeReason = reason;
        // publishes AccountFrozenEvent
    }

    public void addMiles(long miles) {
        if (status != AccountStatus.ACTIVE) {
            throw new IllegalStateException(
                "Cannot accrue miles to "
                + "non-ACTIVE account");
        }
        this.balance += miles;
    }
}
