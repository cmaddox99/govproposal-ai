The Avatar Workflow: Domain Intelligence That Powers Everything

What Is an Avatar?

An avatar is a constitutional intelligence file that tells AI agents exactly who they are working with — the product domain, the technology stack, the laws that apply, the known patterns, and the real codebase evidence.

"Without avatars, every AI response is generic. With avatars, the agent is a constitutional expert in your domain — Check-In, Booking, Android Kotlin — before you type a single prompt."

Two Types of Avatars

🏷️ Product Type

What the product does — journeys, personas, laws, OKR patterns, domain objects

⚙️ Technology

How it's built — stack patterns, known antipatterns, TDD conventions, CI requirements

The Avatar Clinic: 6-Phase Workflow

Phase 0 Preflight — identity & registry checks
Phase 1 Identify — confirm all 5 target avatars in registry
Phase 2 Scan — compliance audit against constitutional schema
Phase 3 Discover — surface domain patterns from real codebase
Phase 4 Enrich — embed real code evidence into avatar guidance
Phase 5 RAG Validate — confirm AI retrieves correct context (≥85%)
Phase 6 Commit — index.yaml stamped, artifacts rendered & committed

The Flat Line Problem

In 90 days the team shipped 3,191 commits — an extraordinary velocity. Source code grew +11.7%. But every quality dimension scored the same in December as in March. The codebase is getting bigger without getting better.

Confirmed Critical Defects (Production Paths)

  • 🔴 Memory Leak: BookingViewModel — 2 RxJava subscriptions never disposed after onCleared()
  • 🔴 Race Condition: CheckInManagerV3 — TSA flag reset before async call completes → infinite re-trigger risk
  • 🔴 Crash Path: CheckInManagerV3 — missing return after error dialog iterates empty list
  • 🟠 Logic Errors: 5 more confirmed bugs in operator precedence & boolean logic

Root Cause: Structural Patterns

🗿 God Objects

BookingViewModel: 2,286 LOC, 8 concerns, 3 reactive frameworks in one class. CheckInManagerV2/V3: two ~2,000 LOC classes with 70% structural duplication.

🔀 Mixed Reactive Paradigms

RxJava + Coroutines + LiveData + Compose State all in the same codebase — sometimes the same class. Every developer must understand all 3 to safely touch BookingViewModel.

✅ Bright Spots to Build On

AncillaryOffersFlowStateMachine — exemplary reference implementation. Sealed class adoption up 22.7% in 90 days. Repository pattern well-established.

  • Instructor-led classroom lectures
  • Generic exercises on toy codebases

  • Learning stays in the classroom
  • No connection to what the team will actually do in Engage

Constitutional Learning (Wave 4)
