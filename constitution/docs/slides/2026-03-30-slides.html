Atomic TDD Law (ENG-4.1)

The Core Practice — NON-NEGOTIABLE

❌ WRONG

  • Write 5 tests
  • Then write code for all
  • Hope they all pass

✅ RIGHT

  • Write 1 test
  • Make it fail (RED)
  • Write minimum code (GREEN)
  • Refactor & Repeat
Why? One test at a time creates a tight feedback loop. You always know exactly what you're working on.

The 6-Step Cycle

1. RED → 2. GREEN → 3. REFACTOR → 4. VERIFY → 5. UPDATE → 6. COMMIT
StepAction
REDWrite ONE failing test
GREENWrite MINIMUM code to pass
REFACTORImprove without changing behavior
VERIFYPass 3 Gates (Tests + Lint + Static)
UPDATEMark task complete in tasks.md
COMMITConventional commit message
Skipping steps breaks the cycle. The discipline IS the value.

VERIFY = 3 Gates

All Must Pass Before Commit

Gate 1: Tests ✅

  • All tests pass (green)
  • Coverage ≥ 90% for new code

Gate 2: Constitution-Lint ✅

  • aa-constitution-lint .
  • No law violations

Gate 3: Static Analysis ✅

  • Cyclomatic complexity ≤ 10
  • Cognitive complexity ≤ 7
ALL 3 GATES MUST PASS BEFORE COMMIT

Time to ProductivityNew dev to first commit< 2 weeks
Agentic SDLC ComplianceConstitutional adherence> 90%

Anti-MetricWhy It's Harmful
